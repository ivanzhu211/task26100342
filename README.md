# 双轨制奖金周结算引擎

Python + SQLite 实现的二叉安置树双轨制奖金周结算，支持迟到业绩的回溯重述。

## 用法

```python
from bonus_engine import Engine

e = Engine("state.db")          # 状态存 SQLite，关掉重开可接着结算
e.enroll(1)                     # 根节点
e.enroll(2, 1, "L")             # 挂到父节点空侧
e.post_volume(2, 1, 300, "o1")  # 业绩（可迟到、可为负退货）
batch = e.settle()              # 结算当前未结周，返回批次
run = e.get_run(1)              # 读历史批次（不可变）
e.close()
```

## 规则

- 每周：`L = 左结转 + 左子树当周业绩`，`R` 同理；本人周业绩 ≥100 点活跃。
- 活跃时 `m = min(L, R)`，奖金 `min(m*10, 200000)` 分；两侧各扣 `m`（封顶截掉部分照样扣）。
- 每侧结转上限 20000 点，多出作废；第 1 周结转为 0。
- 批次每分销商一行：本周奖金、对旧周调整、本次实发、结算后欠款。
- 欠款规则：`实发 = max(0, 应发 - 旧欠款)`，`新欠款 = max(0, 旧欠款 - 应发)`，
  保证 `历次实发之和 - 当前欠款 == 全量重算累计奖金 S`。

## 迟到业绩的增量重述

- `post_volume` 把业绩累加进所属人 `(dist, week)` 的 `own` 及全部上线的
  `left_v/right_v`；若该周已结算，把所属人及上线记入 `dirty`（最早受影响周取小）。
- `settle` 只对 `dirty` 中的分销商，从各自最早受影响周重算到上次已结周，
  差额汇总为该批次的“对旧周调整”；不从第 1 周重放全体分销商。
- 已生成批次落库后不再修改；更正只体现在之后批次的调整里。

## 测试

```
python3 -m unittest discover -s tests -v
```

- `tests/test_random.py`：300 节点随机树跑 30 周，穿插迟到业绩与退货，
  每批用独立参照实现（`tests/reference.py`，全量从第 1 周模拟）核对等式，
  并校验所有旧批次逐字段未变、中途关库重开可续算。
- `tests/test_chain.py`：迟到业绩把旧周从不活跃变活跃，结转与封顶连锁改变；
  退货追回额超过随后两周应发，欠款跨批次扣完。
- `tests/test_scope.py`：单条迟到业绩的重算范围不超出所属人及上线、不早于所属周。
