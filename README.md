# task26100342

双轨制奖金周结算引擎（Python + SQLite），支持迟到业绩的回溯重述。

## 用法

```python
from bonus_engine import Engine

eng = Engine("state.db")          # 状态存于单个 SQLite 文件，可关掉再打开
eng.enroll(1)                     # 根节点
eng.enroll(2, 1, "L")             # 安置到父节点空着的一侧
eng.post_volume(2, 1, 150, "o1")  # 记业绩；week 可以是任何已结算周（迟到业绩）
batch = eng.settle()              # 结算当前未结周，返回批次
eng.get_run(1)                    # 读历史批次（批次不可变）
eng.close()
```

批次里每个分销商一行：本周奖金、对旧周的调整、本次实发、结算后欠款。
不变式：对每个分销商，历次实发之和 − 当前欠款 ≡ 用当前全部已知业绩
从第 1 周逐周算到本周的累计奖金。

## 设计要点

- `week_vol`：记账时即把业绩沿上线逐层累加到各祖先当周的左/右子树聚合。
- `week_state`：每个分销商每个已结算周的奖金与结转，供增量重算从中间周接续。
- `dirty`：迟到业绩（属于已结算周）把所属人及全部上线标脏并记最早受影响周；
  `settle` 只对这些分销商从各自最早受影响周起重算，其余人只算本周。
- 财务：重述差额计入下一批次的"对旧周的调整"，旧批次任何字段不再变；
  差额为负时形成欠款，从以后应发里扣回，欠款大于 0 时实发为 0。

## 测试

```
python3 -m pytest tests/ -q
```

- `tests/test_fuzz.py`：随机树 + 大量迟到业绩/退货，每次结算后与独立的
  全量重放参照实现（`tests/reference.py`）逐字段核对，并校验旧批次不可变。
- `tests/test_restate.py`：迟到业绩把旧周从不活跃翻成活跃引发结转/封顶连锁改变，
  再退货使追回额跨批次扣完。
- `tests/test_touch.py`：单条迟到业绩时重算范围不超出所属人及上线、不早于该周。
- `tests/test_persist.py`：关掉再打开接着结算。
